# Chapter Map and Reading Session

Adapted from the existing reading-session reference; the book index remains the single current-state entry and chapter/session notes remain history.

## Onboarding and longer plans

Reuse a known title, author, verified edition/ISBN, actual table of contents, text access range, learning goal, available time and teaching preference. Unknowns stay unknown. Ask at most the few missing details needed to begin, not a questionnaire. If only metadata is available, plan tentatively by the supplied contents; do not explain unseen pages. Metadata inspection is not reading completion.

Make the long plan from actual conceptual units and goals, not equal chapter allocations. Allocate slower sessions to dense arguments, faster reading to examples/repetition; treat time estimates as revisable. Store the plan in the book index, with proposed units and checkpoints. Missed sessions do not create catch-up debt. Review only important gaps or concepts whose understanding needs refresh; store concrete review prompts/locators in the index. This is reader-driven review, not automatic scheduling.

## Map once, revise when evidence or goals change

Read available chapter headings, opening/conclusion and relevant text. Record edition, actual accessed range and locators. A contents list alone supports structural navigation, not a verified argument map. Label local/provisional maps explicitly. Identify the chapter's problem, its central claims/relationships, links to previous reading, and usually 3–5 priorities; do not fill a quota.

| Class | Structural importance | Default teaching |
|---|---|---|
| A core | Thesis, essential mechanism or argument, later dependency | Deepen only where needed; move on when understood |
| B supporting | Evidence, distinction or representative example that clarifies A | Light check if useful, at most 1 per subsection |
| C secondary | Repeated illustration or detail whose omission preserves the argument | Explain briefly, normally no check |
| D skimmable | Redundant or weakly relevant to this reader's goal | Offer skimming, no unsolicited test |

Assess author purpose, argumentative dependencies, context and reader goals; neither frequency nor paragraph length establishes importance. Split an experiment's logic from its incidental names/dates. Historical/cultural/ethical context can be central. Reader interest can raise discussion priority; it cannot raise evidence strength. “Most important 20%” is a legacy teaching heuristic, not an empirically established percentage or mastery threshold.

Show a short focus statement or answer-free outline. An explicitly requested map/summary may be more detailed, grounded only in supplied text. Revise a map with reasons; do not create a fresh conflicting map each session.

## Question decisions and adaptation

Use the cumulative budget in SKILL.md across turns, pauses, recovery and role changes. The count includes an opening understanding check, example tests and reworded probes; multiple independent checks in one sentence count separately. An unused budget is not a reason to ask. An explanation can be the correct intervention in every preference mode.

Already understood: acknowledge and advance. Partial understanding: name the specific gap and offer a hint/explanation. Major error: correct with an actual source and a relevant counterexample, then check only if useful and within budget. Active reader question: answer first. Fatigue or stopping: close, even mid-concept. Requested depth: allow expansion and record scope/budget changes without mechanically capping the reader's own questions.

Priority questions concern what problem a passage addresses, how claims relate, why evidence supports an argument and how it connects to preceding ideas. Do not repeatedly test names, dates or decorative stories. Analogies aid understanding but do not verify mechanisms.

## Start, pause and end

The opening should recover the last actual result, proposed range, priority/goal and only the needed review. Record planned start → stop and whether the stop heading is included; unknown page numbers stay blank. Use titles, EPUB member/anchor, PDF file page or separately verified printed page. Select boundaries by density, difficulty, conceptual completeness and feedback, not a universal page/time quota.

Session states: planned → active → completed or paused. Start numbering when introduced; do not invent numbers for old unnumbered conversations. Resume a paused session with its ID and cumulative questions. Tool configuration or casual discussion does not become a learning session. “Completed session” means the session ended as recorded, not mastery of its whole plan. Store actual range separately from planned range.

Close in a light sequence: what mattered (only as many points as warranted), significant unresolved issues, useful connections, Next Session. Next has a known start, explicit stop/inclusion, goal, reason and important carry-over issues. On early stop, continue the uncompleted concept first. If the next unit's endpoint cannot be determined, use a grounded provisional beginning and request only the missing locator. At book end, plan review/application without new reading pages.

If a prior section's text and the reader's actual explanation are both missing, do not reconstruct its knowledge takeaways from a heading. State that limitation and close using the supported actual stop and Next plan. A source-limited close can omit substantive takeaways; it must still respect stop/budget and retain continuation.

Save actual notes first, canonical progress/Next second, verify, then report what was actually saved. Archives never replace current state. Home pages can link to the book index; they should not maintain a second full progress table. Review-only sessions explicitly record no new reading. Explicit no-save and denied access still receive a copyable Next plan.
